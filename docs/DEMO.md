# B3 验收演示脚本

建议演示时长：10–15 分钟。全程使用模拟数据；任何结论均以“辅助参考”为前提。

## 0. 准备

### 启动

单服务演示：

```bat
cd frontend
npm install
npm run build

cd ..\backend
py -m pip install -r requirements.txt
py -m uvicorn app.main:app --host 127.0.0.1 --port 8000
```

打开 <http://127.0.0.1:8000>。

开发模式：前端 `npm run dev`（5173），后端 `uvicorn --reload`（8000），打开 <http://127.0.0.1:5173>。

首次启动自动生成演示数据。若需恢复初始演示状态：

```bat
cd backend
py -m app.seed --force
```

> `--force` 会删除当前数据库所有业务数据并重建，仅用于演示环境。

## 1. 人才驾驶舱（约 1 分钟）

1. 使用 `admin` 登录。
2. 进入 **人才驾驶舱**：
   - 指出教师总数、成果、项目、教学学时、社会服务、数据待核验六类指标。
   - 切换学院/学科/职称/年份，说明筛选同时作用于教师和其关联记录。
   - 查看年度成果、学院分布、职称/学历结构、年龄梯队与数据质量。
3. 点击 **人才盘点**：
   - 查看学院职称/学历结构表、人才规划缺口、数据质量。
   - 点击 **导出报告**，打开 Excel，展示“人才盘点概览 / 学院职称结构 / 学院学历结构 / 年度成果 / 人才规划缺口 / 数据质量”工作表。

**讲解点**：所有数字来自数据库查询；年龄使用 2026 年当前年份计算；模拟数据标记。

## 2. 数据导入与质量（约 2 分钟）

1. 进入 **数据管理**：
   - 下载“教师档案导入模板”。
   - 上传 `samples/teachers_import_demo.csv`。
   - 展示结果：成功 1、失败 1、重复 1。
   - 打开 **错误明细**：重复编号、非法职称、邮箱格式等中文原因；导出错误 CSV。
2. 上传 `samples/outputs_import_demo.csv`：
   - 展示“教师不存在”“同文件重复成果”识别。
3. 切换到 **导入批次** 与 **数据质量**：
   - 查看批次统计、错误导出、待核验教师、疑似重复、无成果教师。

**讲解点**：导入不是“整文件成功/失败”，而是逐行校验并保留错误明细；导入教师默认 `pending` 待核验，来源标记为“导入:文件名”。

## 3. 教师档案与智能画像（约 2 分钟）

1. 进入 **教师档案**，搜索 `B3T9001`：
   - 查看刚导入的教师；打开详情抽屉，展示关联计数。
2. 在 **教师档案** 中点击任意教师行的“画像”（或详情抽屉中的“查看多维画像”），进入 **智能画像** 详情页：
   - 展示成果/项目/教学/服务统计卡、年度趋势、类型分布、教学工作量。
   - 指出数据完整度、缺失字段、标签、指标口径。
   - 点击 **生成 AI 摘要**：
     - 当前未配置 LLM Key，显示 `mode=local`；
     - 摘要完全基于数据库统计事实；
     - 提示“没有配置 API Key，使用本地规则生成”。

**讲解点**：画像不是手写文案；指标口径随页面返回；AI 仅辅助归纳，失败自动本地回退。

## 4. 导师匹配与师生匹配度（约 3 分钟）

1. 进入 **导师匹配**：
   - 在“学生需求”标签查看 20 个学生画像。
   - 选择一名学生，点击“创建匹配任务”。
   - 调整权重：研究方向 40%、具体主题 25%、培养需求 20%、容量 15%（可自定义，系统自动归一化）。
   - 创建并执行。
2. 打开结果：
   - 推荐列表按加权总分排序，展示各维度分、原因、权重说明。
   - 展开“被排除教师”：
     - 未取得导师资格；
     - 招生状态未开放/已满；
     - 指导容量已满。
   - 强调：**硬性条件不满足的教师即使方向匹配度很高，也不会进入推荐**。
3. 对第一名点击“人工确认”，填写备注，再打开确认状态。

**讲解点**：TF-IDF + 关键词覆盖全部本地计算；原因是真实得分；人工确认独立于算法分；系统不自动分配导师。

3. 进入 **师生匹配度**：
   - 默认已选择学生需求；点击“开始量化”。
   - 查看 0-100 总分、四个维度的“得分 × 权重 = 贡献分”、A-D 参考等级和硬条件列。
   - 切换“指定教师”，点击“开始量化”，查看单教师大分数卡、分项进度条和完整评分理由。
   - 修改权重后重新量化，展示权重如何改变总分。
   - 强调：A-D 阈值是演示配置；硬条件不通过的教师显示规则分，但不进入有效推荐；系统不自动分配导师或给出录取结论。

## 5. 职称申报材料归集（约 2 分钟）

1. 进入 **职称申报**：
   - 选择演示批次，查看批次、申报要求和教师范围。
   - 选择一名教师，点击“归集材料”。
2. 查看材料核验：
   - 状态包括已匹配、缺项、待核验、重复、信息冲突、人工确认、人工驳回。
   - 展示完成率、必填缺项、各要求达成情况。
   - 选择一条缺项/待核验材料，人工确认或驳回并填写备注。
3. 重新查看汇总：
   - 完成率随人工确认变化。
   - 导出 Excel，展示“申报汇总 / 要求达成情况 / 材料明细”。

**讲解点**：申报条件是可配置示例，不代表真实政策；系统只检查数据完整性/一致性，不验证成果真伪；自动归集不会覆盖人工确认/驳回记录。

## 6. 人才引进辅助评估（约 2 分钟）

1. 进入 **人才引进**：
   - 选择一个演示岗位，查看岗位要求（学历、最低成果数、方向、权重）。
   - 查看候选人列表，执行“匹配评估”。
2. 查看结果：
   - 硬条件不满足者（学历/成果数）排名为空，并显示缺口。
   - 满足者展示方向、成果、项目、教学维度分、总分、排序。
   - 展开证据：成果/项目/教学证明、来源、待核验字段。
3. 对候选人填写人工评审（进入面试/淘汰/已评审）和备注。
4. 可选：导入 `samples/candidates_import_demo.csv` 到当前岗位，展示成功 1、重复 1。

**讲解点**：系统只给辅助建议，不自动录用或淘汰；证据与待核验字段随结果展示；删除仍有候选人的岗位会被 409 阻止。

## 7. 权限、脱敏与审计（约 1 分钟）

1. 使用 `viewer` 登录：
   - 教师列表中的手机号/邮箱已脱敏；
   - 打开画像，联系方式不出现在教师对象中；
   - 新增/修改按钮不可用；直接调用写接口返回 403。
2. 切回 `admin`：
   - **系统设置** 查看 LLM 状态、评分权重、人才规划、用户管理。
   - 查看 **审计日志**：登录、导入、匹配、材料确认、评审等写操作均有记录。
3. 说明：仅角色级权限，生产需增加学院/学科数据范围。

## 8. 稳定性与自动化测试（约 1 分钟）

```bat
cd backend
py -m pytest -q
```

展示 **18 passed**：健康检查、前端深链接、CRUD、导入错误、画像一致性、统计筛选、导师硬条件、匹配度量化、申报状态、人才引进、权限脱敏、LLM 回退、重启持久化、导出可读性等。

重启后端后再次打开页面，数据仍在；首次演示前可用 `py -m app.seed --force` 恢复初始状态。

## 常见演示问题

| 现象 | 处理 |
| --- | --- |
| 前端 404 / 空白 | 确认已 `npm run build`；单服务模式下确认 `frontend/dist` 存在 |
| 登录失败 | 确认首次启动已生成用户；执行 `py -m app.seed --force` 重置演示库 |
| 端口占用 | 修改 `--port`，并同步修改 `frontend/vite.config.ts` 的代理目标 |
| 导入重复数变化 | 同一文件重复导入会命中已有记录，属预期；可先重置演示库 |
| AI 摘要为本地模式 | 未配置 `LLM_API_KEY`，属预期；配置后仍只发送脱敏统计事实 |
| 图表不显示 | 检查浏览器控制台与 `/api/analytics/dashboard` 响应；图表依赖真实数据 |
